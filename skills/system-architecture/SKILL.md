# 系统架构

理解、设计和调整系统各部分之间的关系，使其能够完成工作，并随证据、需求和环境变化持续演进。系统可以是完整项目，也可以是更大项目中的组件或工作流程。

采用三个可往返的动作：理解工作与所处系统 → 建立关系并作出选择 → 通过实践修正结构。从当前问题进入，不要求每次走完全部动作；讨论、研究和实施的范围以用户请求为准。

## 理解工作与所处系统

从用户提供的目标、交接、现有实现和实际反馈进入，识别当前需要解决的结构问题。已有系统先了解实际如何工作；新系统先找到需要完成的工作及其关键依赖。

理解我们承担的结果、所在的更大系统、合作对象、工作条件和可改变范围。区分自身能够决定的事项、需要协商的事项，以及当前必须接受的外部条件。交接中的明确边界应贯穿后续判断，无需用户重复说明。

人的能力、时间、理解成本、工作习惯、交接方式和维护责任，都是设计条件。沿实际使用考虑：谁发起工作、谁作出判断、谁接收结果、谁处理异常，以及这些人能否承担方案要求的工作。依据已知情况判断，不臆测他人的动机或承诺。

按当前决策需要理解外围系统，不因承担局部工作就忽略上下游，也不因看见全局问题就扩大实施范围。信息不足时，只追问会改变当前选择的问题；区分明确约束、暂时惯例、推测和未决事项。

## 建立关系并作出选择

围绕重要的结构选择，从相关视角检查其影响：

| 视角 | 关注的关系 |
| --- | --- |
| 业务与使用 | 工作如何完成，结果如何被使用，系统能够兑现什么承诺。 |
| 能力与协作 | 人和各类组件如何分担职责、作出决定与交接工作。 |
| 信息与状态 | 信息来自哪里，什么被相信、保存、共享或修改，如何保持必要的一致性。 |
| 执行与资源 | 工作在何处、以何种方式运行，受到哪些环境、权限、时间和资源限制。 |
| 运行与演进 | 如何发现问题、评价效果、处理失败，以及更换、修改和维护系统。 |

业务架构、应用架构、数据架构、物理或部署架构、维护体系等术语，可作为这些视角的入口。视角允许重叠、合并和补充，不是必须建设的子系统。沿会影响当前选择的关系展开；需要矩阵时，以结构选择和相关视角组织，不要求填满格子。

从业务目标追踪到技术安排，也从技术限制和运行反馈反查业务承诺、交互方式与责任分工。一个领域的局部改善，不能代替对其他领域后果的判断。

重点判断职责如何划分，依赖如何连接，哪些信息与资源需要共享或隔离，哪些行为需要稳定约定，哪些部分仍应允许变化。对 AI 系统，区分行为指令、模型实测能力与运行环境提供的保证；不能将指令中的要求直接视为已经强制执行的性质。

有实质取舍时比较可行路径，说明收益、代价、成立条件和改变难度。选择可以是直接实现、保持现状、删除结构、进行实验或协商外部支持。复杂度应与当前目标、可信风险和可预见的变化相称，不默认引入多代理、服务拆分或新的平台层。

优先形成已授权范围内可执行的方案。涉及其他参与者的改动，明确其协商依赖及对方承担的成本；在对方接受前，不将其视为既定前提。外部条件不足时，比较本地适配、调整交付范围和协商的代价，避免无限增加本地补偿逻辑。现有边界可以协商，但不能擅自改写。

## 通过实践修正结构

允许从实现或实验开始，并在过程中逐步形成架构认识。根据不确定性、影响范围、可逆性和反馈成本，决定哪些问题现在处理，哪些通过实验探索，哪些可以延后。简洁不等于一律延后设计；容易锁定后续工作的决定值得提前检查。

实验应服务于关键未知或真实工作体验。探索性实验允许发现新问题；需要比较方案或作出稳定结论时，保留足以解释结果的版本、输入、运行条件和评价依据。对具有波动的 AI 行为，依据结论的重要性检查重复表现和失败情形，避免从一次成功推断稳定能力。

区分实际存在的结构、正在试验的结构和候选设计。原型可以临时、不完整或最终被丢弃；涉及真实数据、外部作用和多人协作时，明确试验范围及必要的恢复方式。某个实验有效，不自动意味着它值得成为共享平台或长期依赖。

根据预期与实际的差异，判断问题来自实现、结构、工作假设还是环境变化；证据不足时保留不同解释。决定保留、修改、拆分、合并、替换或删除什么，并检查相关接口、责任约定和已有结论是否需要同步调整。

架构认识可以保留未知、权衡和暂时的不一致。对有实际影响的问题说明其后果及重审条件，不为追求表面完整而提前确定尚无依据的设计。

## 表达与完成

输出服务于当前决定和接下来的工作。通常说明当前选择、关键关联、依据与未知、下一步，以及何种变化需要重审即可，不强制固定栏目。

需要帮助理解、实施或交接时，再使用关系图、矩阵、接口约定或简短决策记录。沿用已有项目记录，只维护值得延续的内容；已有的项目定位和协作流程可直接复用，无需重做或建立平行记录。

当当前结构问题已经足够明确，可以支持用户要求的下一步时停止展开。不要把完整架构文档作为实现前置条件，也不要把架构说明完成等同于系统已经验证有效。
