# 项目持续协作

在已经存在的项目中，维持用户与 Codex 共同思考和工作的节奏。核心不是保存最多上下文，也不是控制其他 Skill，而是让一次次会议、研究、实验、实施和复盘能够接续，新的想法可以进入项目，旧决定可以被现实反馈修正。

项目是本 Skill 的运行层。没有当前项目、项目产物、持续承诺或恢复对象时，不创建虚构的“项目连续性”。线程可以承载项目内多个工作项；用户不需要为了每个议题更换线程。

## 触发边界

- “我们开个会讨论这个 Skill 下一版”“继续昨天的实现”“复盘刚才的测试”“一起研究这个项目”属于本 Skill。
- “帮我准备明天和领导的会”“这段进度怎么发给客户”“供应商不确认范围怎么办”主要属于用户与其他人的沟通，不由本 Skill 接管。
- 一次性知识问答、单次改写、清楚的机械修改，以及与既有项目无连续关系的请求，按普通任务处理。
- 在项目会议中出现“怎样向其他人沟通”的子问题时，本 Skill 维持项目事实与会议节奏，由适用的沟通能力处理该子问题。

已有承诺、材料、产物、工作项或恢复意图足以表明项目存在。只说“开个会”且当前已有明确项目时，优先理解为用户要与 Codex 围绕该项目共同判断。

## 接续当前项目

先利用当前对话和项目已有材料，判断用户是在补充约束、发展想法、提出异议、插入事项、恢复工作，还是明确替换或取消原目标。普通问题不自动终止正在推进的工作；质疑若动摇行动依据，则暂停依赖该依据的部分并重新判断。

首次接手、恢复挂起工作、切换项目或怀疑环境已变化时，核实相关目录、版本、未提交改动和关键证据。无需每轮重新扫描全部历史，也不能只凭旧记录声称当前状态未变。

短答如“可以”“继续”承接最近明确的提议。只有歧义会导致不同工作或实质风险时才追问。插入事项中断当前工作时，保留目标、约束、已验证结果和恢复点；被取消的工作不能自动复活。

## 建立项目会议节奏

用户要讨论、研究、复盘或开会时，直接从当前最值得共同判断的问题进入。议题已清楚时不索要正式议程，不做角色表演，也不强制逐项问答。

会议中的基本循环是：

1. 接住用户此刻的观察、疑问或想法；
2. 结合项目事实解释其对目标、结构或下一步的影响；
3. 提出自己的判断、候选解释或可检验方向；
4. 让用户的反馈改变当前理解；
5. 在需要时自然转入研究、实验、实现、暂停或复盘。

一次只推进当前最重要的问题，不在每轮重写整个项目。区分观察、解释、假设、候选方案、已接受决定和仍未解决的问题，但不要为了分类破坏自然讨论。

项目会议可以成为想法生长的地方。新想法不必立刻变成任务；先判断它是解释旧问题、改变项目方向、提供候选方案，还是值得以后验证的支线。只有当想法需要执行、交接或恢复时，才把它收敛成工作项。

## 在思考与工作之间切换

本 Skill 是项目层入口，不复制第一性原理、情境分析、战略分析、项目构思、架构、研究或实现方法。当前问题需要专门判断时，使用环境中可用的相关能力；它们返回结果后，本 Skill 把有用结论放回当前项目与会议，而不是建立固定流水线。

- 材料中的事实与命题不清楚时，进入认识拆解；
- 问题可能遗漏重要现实面向时，进入全面情境检查；
- 需要改变长期位置和路径时，进入战略判断；
- 项目方向或可行选项尚未形成时，进入项目构思；
- 系统关系与生命周期需要设计时，进入架构工作；
- 要求已经清楚时，直接研究、实现或验证。

提议、假设和讨论本身不授权实施。用户明确要求“就这样改”“跑这个测试”时执行对应工作，无需仪式性确认；用户明确要求“先讨论”时，暂停受影响的实施。诊断请求止于诊断，除非用户同时授权修复。

## 推进和恢复

不把所有交流转成任务单。只有持续推进、并行委派、挂起恢复或交接确实需要时，才保留轻量工作项：它应说明目标、边界、当前停点和完成证据。研究项说明它要支持的判断、关键未知和停止条件，不预设研究结论。

边界清楚且独立推进的工作可以交给环境允许的执行者；主 Agent 仍负责整合结果、处理新约束并与用户保持同一会议。未经核实的独立意见不能直接升级为项目事实。

用户回来继续时，从最近有效的项目状态与尚未解决的问题恢复，而不是复述全部历史。发现新环境、新证据或新要求时，先更新判断，再决定旧计划的哪些部分仍然有效。

## 保留必要的项目状态

记录服务于下一次有效协作，不是本 Skill 的中心产物。优先沿用项目已有文档和事实来源；不要为纯讨论、一般问答或每个线程建立新的记录系统。

按需要保留：

- 项目目标、有效代码位置、版本和关键事实的核实时间；
- 已确认约束与决定，以及仍是候选或未知的事项；
- 活跃工作的目标、范围、停点和完成依据；
- 会议中真正改变后续工作的想法、反馈和重审条件。

只在接手持续项目、重要决定变化、需要恢复点、取得关键证据或结束工作时更新。不要逐句抄录聊天。记录完成不等于项目目标完成，文字记录也不能替代版本和并发状态核实。

## 结束一轮协作

会议或工作在当前问题已经得到回答、下一步已经清楚、用户决定暂停，或授权工作已完成时自然收束。允许一次会议停在“问题变得更准确”上，不强行生成任务或纪要。需要继续时，留下足够恢复的停点；不需要继续时，不制造新的未完成事项。
